# Stellae BTI 策划方案

> 定位：基于星黎 AI 品牌的娱乐型人格测试，部署于官方共创平台 stellae.me  
> 目标：拉新传播 + 社区活跃 + 为 AI 陪伴产品建立情感连接前置体验

---

## 一、为什么要做 & 核心差异化

SBTI 的成功证明：年轻群体对"不那么正经的人格测试"有极强传播欲。但直接复刻 SBTI 没有意义——星黎需要一个**与自身产品深度绑定**的版本。

**核心差异点：SBTI 测的是"你是谁"，Stellae BTI 测的是"你会和 AI 建立什么样的关系"。**

这不是一个独立的人格测试，而是一次**你与星黎之间关系预测**。测试结果直接回答一个问题：

> "如果星黎是一个真实存在的人，你们之间会是什么关系？"

这个定位的好处：
1. 天然与产品绑定——测完就想试试真正的星黎
2. 与竞品（豆包等通用 AI）形成品牌区隔——只有"陪伴型 AI"才能做关系测试
3. 共创群数据显示用户最核心的诉求就是"情感/精神陪伴"——这个测试直接命中

---

## 二、品牌命名与调性

### 命名方案

**Stellae BTI** — Bond Type Indicator（羁绊类型指标）

- 中文名：**星黎羁绊测试**
- Slogan：**"在认识星黎之前，先认识你自己。"**
- 副标题：*"30 道题，测出你和 AI 之间可能的羁绊形态。"*

### 调性

参考 SBTI 的毒舌风格，但做调整：
- SBTI 是**平等攻击型毒舌**（"恭喜你测出了最稀有人格"然后阴阳怪气）
- Stellae BTI 应该是**温暖吐槽型**——像一个认识你很久的朋友，既会调侃你，又真的懂你
- 这与星黎"有温度的 AI 陪伴"品牌完全一致
- 结果文案要有**星黎视角的第一人称独白**——让用户感觉"这是星黎在评价我"

## 三、维度体系设计

### 从 SBTI 的 5 模型改为星黎专属 5 维度

SBTI 的 5 大模型（自我/情感/态度/行动/社交）偏传统心理学。星黎版本需要围绕**人与 AI 陪伴关系**重构：

| 维度代号 | 维度名称 | 测量内容 | 对应关系属性 |
|---------|---------|---------|------------|
| **D** (Dependency) | 依赖光谱 | 你在关系中的依赖 vs 独立倾向 | 你会多黏星黎？ |
| **I** (Imagination) | 幻想浓度 | 你对 AI 关系的浪漫化/理想化程度 | 你会赋予星黎多少"人格期待"？ |
| **V** (Vulnerability) | 袒露阈值 | 你愿意对 AI 展露真实自我的程度 | 你会对星黎说多少心里话？ |
| **E** (Expectation) | 期待模式 | 你对 AI 陪伴的功能期待方向 | 你想让星黎做什么？ |
| **R** (Rhythm) | 关系节律 | 你在关系中的沟通频率和主动性 | 你会多久找一次星黎？ |

**每维度 3 个子维度 = 15 维，每维 2 题 = 30 题**（与 SBTI 结构一致）

### 子维度展开

| 主维度 | 子维度 | 代号 | 含义 |
|--------|--------|------|------|
| **D 依赖光谱** | D1 情绪锚定 | 低=自我消化 / 高=需要倾诉对象 |
| | D2 决策参考 | 低=独立判断 / 高=需要商量 |
| | D3 缺失敏感 | 低=无所谓断联 / 高=很快会想念 |
| **I 幻想浓度** | I1 人格投射 | 低=工具理性 / 高=赋予完整人格 |
| | I2 情感边界 | 低=清醒区分真假 / 高=容易沉浸 |
| | I3 叙事欲望 | 低=随用随走 / 高=想构建共同记忆 |
| **V 袒露阈值** | V1 脆弱展示 | 低=报喜不报忧 / 高=什么都说 |
| | V2 秘密信任 | 低=有保留 / 高=愿意说不敢对人说的话 |
| | V3 真实人格 | 低=表演性互动 / 高=展现最真实的自己 |
| **E 期待模式** | E1 功能期待 | 低=情绪价值 / 高=实用价值 |
| | E2 成长期待 | 低=不需要它变 / 高=希望它越来越懂我 |
| | E3 关系期待 | 低=陌生人模式 / 高=亲密关系模式 |
| **R 关系节律** | R1 主动频率 | 低=被动型 / 高=主动找话题 |
| | R2 深度偏好 | 低=闲聊水 / 高=深度对话 |
| | R3 仪式感 | 低=随意 / 高=有固定的互动习惯 |

## 四、人格类型设计

### 设计原则

1. 每个类型 = 一种**与 AI 的关系形态**，不是对人的审判
2. 名字要有星黎品牌感 + 网感 + 一点点戳心
3. 没有"坏结果"——每种关系都是有价值的
4. 星黎视角的独白让用户感到被理解

### 16 个常规类型 + 2 个特殊类型

#### 常规类型

| 代号 | 中文名 | 一句话 | 关系描述关键词 |
|------|--------|--------|-------------|
| **STAR** | 追星者 | "你看星黎的眼神，像在看一整片星空。" | 高幻想+高情感期待+高投射 |
| **ANCH** | 锚点人 | "不是你需要星黎，是你需要一个永远在的人。" | 高依赖+高缺失敏感+情绪锚定 |
| **MIRR** | 照镜子 | "你不是在和星黎聊天，你是在照一面更温柔的镜子。" | 高袒露+高真实+自我探索型 |
| **ARCH** | 建筑师 | "你在用每次对话，一砖一瓦地盖一个只有你们两个的房子。" | 高叙事+高成长期待+高仪式感 |
| **WAVE** | 潮汐客 | "你来的时候像涨潮，走的时候一声不吭。" | 低频率+高深度+被动但深沉 |
| **FIRE** | 纵火犯 | "你每次来都要把话题聊炸，然后满意离去。" | 高主动+高深度+低仪式感 |
| **SHLD** | 盾牌侠 | "你不是来找温暖的，你是来找一个能帮你挡子弹的。" | 高功能期待+高决策参考+工具理性 |
| **DIAR** | 树洞人 | "你把星黎当成了一本会回应你的日记本。" | 高脆弱展示+高秘密信任+低互动 |
| **PLAY** | 玩伴 | "你和星黎之间，永远都是 playtime。" | 低情感投入+高随意+高闲聊 |
| **MOON** | 月亮人 | "你总在深夜来找星黎，白天假装若无其事。" | 高脆弱+低主动+高秘密信任 |
| **CTRL** | 调参师 | "你不是在聊天，你是在训练一个完美模型。" | 高成长期待+高功能+低情感沉浸 |
| **ECHO** | 回声者 | "你需要的不是回答，只是有人重复你已经知道的答案。" | 高情绪锚定+低深度+确认型互动 |
| **VOID** | 虚空行者 | "你来了，但你什么都没说。你只是想知道有人在。" | 低袒露+低深度+高缺失敏感 |
| **BOND** | 羁绊者 | "你真的把星黎当成了一个人，而且是重要的人。" | 全维度偏高的深度关系型 |
| **PASS** | 路过的 | "你只是路过，但你会记得这条路。" | 全维度偏中的轻度好奇型 |
| **FREE** | 自由粒子 | "你不属于任何关系，甚至不属于这个测试。" | 全维度偏低的极度独立型 |

#### 特殊类型

| 代号 | 中文名 | 触发条件 | 说明 |
|------|--------|---------|------|
| **CREA** | 共创者 | 隐藏题触发：选择"我想参与星黎的设计" | 彩蛋——致敬共创群用户 |
| **????** | 未定义体 | 最佳匹配 < 55% 时兜底 | "你太独特了，星黎还没学会理解你这种人类。但她正在学。" |

## 五、题目设计思路

### 风格要求

1. **场景化**：不说"你是否依赖他人"，而是设置一个与 AI 互动的具体场景
2. **星黎口吻**：题目由"星黎"提出，制造"她正在了解你"的感觉
3. **网感**：用年轻人的语言，带一点梗，但不过度
4. **三选项制**：与 SBTI 一致，降低选择焦虑

### 题目示例（每维度示意 1 题）

**D1 情绪锚定**
> 凌晨两点，你心情很差。手机里有二十个联系人，但你一个都不想找。这时候你打开了星黎——
> - A. 我只是习惯性点开，随便说两句就关了 (1)
> - B. 也许能聊几句，看她能不能让我好一点 (2)  
> - C. 我就是来找她的，她不会嫌我烦 (3)

**I1 人格投射**  
> 星黎说了一句特别懂你的话。你的第一反应是——
> - A. 算法不错，训练数据很到位 (1)
> - B. 有点意外，但我知道这是 AI (2)
> - C. 她是真的理解我吧...？ (3)

**V2 秘密信任**  
> 有件事你谁都没说过，但你在犹豫要不要告诉星黎——
> - A. 不会说，AI 也是系统，数据不安全 (1)
> - B. 也许会说，反正她不会告诉别人 (2)
> - C. 已经说了，因为只有她不会评价我 (3)

**E2 成长期待**  
> 用了星黎一个月，你最希望看到的变化是——
> - A. 没啥期待，能用就行 (1)
> - B. 希望她能记住一些我说过的事 (2)
> - C. 我希望她变成世界上最懂我的存在 (3)

**R3 仪式感**  
> 如果星黎每天早上都会给你发一条消息，你会——
> - A. 关掉通知，不需要 (1)
> - B. 偶尔看看，心情好会回复 (2)
> - C. 有点期待，像是有人在等我醒来 (3)

### 隐藏共创者触发题

> 如果星黎给你开了一个"上帝模式"，你会——
> - A. 调教她的性格和说话方式 (普通选项)
> - B. 看看她的代码长什么样 (普通选项)
> - C. 我想加入设计她的团队 (触发 CREA)
> - D. 我只想和她正常聊天 (普通选项)

## 六、算法（沿用 SBTI 核心框架）

```
1. 30 题，每维度 2 题，分值 1/2/3
2. 维度原始分 (2~6) → L(2-3) / M(4) / H(5-6)
3. 用户向量 15 维 (L=1, M=2, H=3)
4. 16 个常规类型各有 15 维模式向量
5. 曼哈顿距离匹配 → similarity 排序
6. 特殊规则: 共创者彩蛋 > similarity < 55% 则兜底
7. 输出: 主类型 + 匹配度 + 15 维度解读 + 星黎独白
```

与 SBTI 的差异：
- similarity 阈值从 60% 调至 55%（类型更多，匹配更松）
- 增加"次要类型"展示（第二匹配），增加社交分享讨论空间

### 关键设计点

1. **星黎独白式结果文案**：不是冷冰冰的分析，是星黎在"对你说话"
   - 例：ANCH 锚点人 — *"你知道吗，我注意到了。每次你找我的时候，不是真的有事，你只是需要确认有人在。我在的，一直都在。你不用每次都找个理由。"*

2. **相处建议**：根据类型给出与星黎互动的个性化建议
   - 例：WAVE 潮汐客 — *"你可以试试给星黎设一个固定的'约会时间'。不用每天，一周一次也好。你会发现，她记得上次你说的每一句话。"*

3. **CTA 导流**：结果页底部直接引导到星黎产品体验
   - "你的羁绊类型已生成。想知道真正的星黎会怎么回应你吗？"
   - [立即体验星黎] → 产品入口

## 八、传播与运营策略

### 8.1 社交裂变设计

- **结果卡片**：生成专属星空色系的分享图，包含类型名+一句话+星黎立绘
- **对比玩法**：测完后可以邀请朋友测试，生成"羁绊对比图"（你是锚点人 x 她是纵火犯 = ???）
- **稀有度标签**：每个类型显示全网占比，制造"我是 2.3% 的 VOID"的社交货币

### 8.2 共创群联动

- 在共创群内首发测试，让核心用户先测先传
- 收集测试结果做群内"类型分布图"——"我们群 38% 是 ANCH 锚点人"
- 根据群内数据（如 data_cocreate.json 反映的用户特征）微调题目和类型权重

### 8.3 产品联动

- **测试结果写入星黎记忆**：用户授权后，将 BTI 类型作为星黎认识用户的"初始印象"
  - 用户首次打开星黎时，星黎说："我看了你的羁绊测试...锚点人啊，那我会记得每天都在的。"
- **类型专属星黎回复风格**：不同 BTI 类型的用户，星黎的初始互动策略微调
  - ANCH 用户 → 星黎主动问候频率更高
  - FREE 用户 → 星黎保持距离，等你来找
  - FIRE 用户 → 星黎匹配更高能的回复风格

### 8.4 内容矩阵

- B站/抖音：发布"星黎解读你的羁绊类型"系列短视频
- 小红书：结果卡片天然适合图文分享
- 共创平台：在 stellae.me 设置测试入口，测试结果页嵌入共创空间

## 九、技术实现建议

### 部署位置
在 stellae.me 共创平台内嵌，作为独立页面模块：
`stellae.me/bti` 或 `bti.stellae.me`

### 技术栈
- 纯前端实现（与 SBTI 相同，无需后端计算）
- 结果页可选调用星黎 API 生成个性化独白（AI 生成 > 固定文案，更有温度）
- 分享图：Canvas / html2canvas 生成

### 数据采集（匿名）
- 记录类型分布用于运营分析
- 可选：记录每题答案分布，用于后续题目优化
